Les 3 versions

FichierUsageOùÉcriture
geosd-admin.htmlIntégration du fichier central, fusion des envois terrainPoste desktop (Chrome/Edge/Opera)Directe sur disque (File System Access API)
geosd-terrain-saisie.htmlSaisie de nouveaux points sur le terrainTablette Android (ou tout mobile)Mémoire locale (localStorage) + envoi mail/partage après chaque point
geosd-terrain-consultation.htmlConsultation des points déjà connus, lecture seuleTablette Android (ou tout mobile)Aucune — fichier local ou dépôt distant

Toutes les trois partagent deux fichiers communs à ne jamais dupliquer : geosd-themes.js (configuration des thématiques, généré depuis le CSV) et geosd-common.css (apparence).

Les fichiers doivent rester dans le même dossier.

Modifier le modèle de champs

Une ligne du CSV = un champ. Cette régénération met à jour les 3 applications en un seul lancement.

  1. Éditer modele-formulaires.csv (Excel, Google Sheets, VS Code...).
  2. Dans un terminal, se placer dans le dossier du projet, puis : 
    python3 generate_themes.py
  3. Vérifier le message OK — N thématique(s) écrites dans geosd-themes.js (partagé par les 3 versions).
  4. Recharger les pages ouvertes dans le navigateur.

Tableau de données (geosd-admin.html)

Bouton « Tableau » dans l'en-tête : liste tous les points avec leurs valeurs complètes — thématique, sous-type, les 7 champs communs (commune, date, heure, auteur signalement, auteur faits, commentaire, fiabilité, détectés automatiquement), une colonne « Détails spécifiques » pour les champs propres à chaque thématique, et les coordonnées.

Respecte les filtres actifs (contrairement aux statistiques, qui affichent toujours tout) — utile pour croiser une recherche/filtre avec un export ciblé.
  • Tri par date, thématique ou commune.
  • Actions directement depuis chaque ligne : Localiser (centre la carte et ouvre le point), Modifier, Supprimer.
  • « Exporter en CSV (Excel) » : fichier ouvrable directement dans Excel (accents corrects). Pas un .xlsx natif — volontairement, pour ne pas ajouter de dépendance externe (SheetJS) au projet.

Statistiques (geosd-admin.html)

Bouton « Statistiques » dans l'en-tête : histogramme (points par thématique et par mois, couleurs identiques à la carte) et tableau détaillé avec totaux par ligne/colonne, plus export CSV.

Toujours calculé sur l'ensemble du fichier, sans tenir compte des filtres actifs sur la carte. Aucune bibliothèque externe — graphique en SVG généré à la volée. Les thématiques ajoutées via le CSV apparaissent automatiquement.

Modifier un point existant

Sur geosd-admin.html et geosd-terrain-saisie.html, cliquer sur un point puis « Modifier » dans le popup rouvre le formulaire pré-rempli avec ses valeurs actuelles.

La position géographique du point n'est volontairement pas modifiable depuis ce formulaire — pour déplacer un point, le supprimer et le ressaisir au bon endroit.

Workflow terrain → bureau

  1. Sur la tablette (geosd-terrain-saisie.html) : facultatif, charger le fichier central existant via « Charger points existants » pour un contexte visuel (points gris, non modifiables). Saisir les nouveaux points normalement.
  2. Après chaque point : un panneau propose « Envoyer par mail » ou « Partager » (fichier .geojson joint via le partage natif Android).
  3. En fin de tournée, « Exporter tout » télécharge un fichier de secours avec tous les points de la session.
  4. Au bureau (geosd-admin.html) : « Intégrer un envoi terrain » — sélection multiple possible, doublons ignorés automatiquement (même identifiant).

Consultation et mise à jour du fichier de référence

Protocole retenu : les agents étant responsables du contenu de leur matériel professionnel, aucun mécanisme d'authentification distant n'est nécessaire. Mise à jour par copie manuelle à la demande :

  1. Le fichier central à jour est disponible sur le dossier réseau de l'entreprise.
  2. À intervalle régulier, copier ce fichier sur la tablette.
  3. Dans la version terrain, bouton « Charger un fichier » → sélection du fichier copié.

Indicateur de fraîcheur automatique : chaque sauvegarde par geosd-admin.html horodate le fichier (updated_at). Les versions terrain affichent cet âge, avec alerte au-delà de 30 jours (réglable dans geosd-themes.js, constante STALE_AFTER_DAYS).

Le mécanisme d'URL de dépôt distant (DEPOT_URL) reste dans le code, désactivé — à réactiver seulement si le protocole manuel s'avère insuffisant.

Installer des raccourcis sur la tablette

  1. Ouvrir geosd-terrain-saisie.html dans Chrome.
  2. Menu Chrome (⋮) → « Ajouter à l'écran d'accueil ».
  3. Répéter avec geosd-terrain-consultation.html.

Architecture technique

  • Aucun serveur applicatif. geosd-admin.html écrit directement sur disque via la File System Access API (Chrome/Edge/Opera desktop uniquement).
  • Format des données : GeoJSON standard, réutilisable dans QGIS.
  • Fonds de carte : OpenStreetMap et IGN Géoplateforme (data.geopf.fr, WMTS ouvert, sans clé).

Limitations connues

  • geosd-admin.html : Chrome/Edge/Opera desktop uniquement. Pas de version mobile prévue.
  • Android ment parfois sur son support de l'écriture de fichiers — les versions terrain n'utilisent donc jamais cette API, indépendamment de ce que le navigateur prétend supporter.
  • mailto a une limite de longueur (~2000 caractères) — utiliser « Partager » pour un commentaire long.
  • Le partage de fichier (navigator.share) dépend des applications installées — à tester sur le matériel cible.
  • Pas de fusion automatique en cas de modification simultanée du fichier central par deux personnes.

Sauvegarde des données

Le fichier .geojson central est la donnée la plus précieuse du projet (le reste est régénérable). Faire une copie datée régulièrement, avant toute séance d'intégration importante.

Pistes d'évolution

  • Champs spécifiques restants pour Phytosanitaires, VTM, FSC, Habitat/espèces protégées, Cueillette.
  • Sous-type « Eau > RCE » à définir.
  • Suivi de l'évolution du support Android de la File System Access API.
